# Compliance checklist

Every item needs **evidence** — a test name, a file, or a published URL — not a tick.
(`architecture.md §17`, `plan.md §17`.)

| #   | Requirement                                                                       | Evidence                                                                                                                                                                                              | Status                                                                 |
| --- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | The consent screen precedes any permission request                                | `ui/AppRoot.kt` — the flow is WELCOME → RATIONALE(+consent) → PERMISSIONS → ENROLL, and the permission launcher is only reachable from the post-consent step                                          | ✅                                                                     |
| 2   | Consent is available in English **and** Bengali                                   | `res/values/strings.xml` + `res/values-bn/strings.xml` (`onb_rationale_*`, `onb_consent_checkbox`)                                                                                                    | ✅ (native-speaker review pending)                                     |
| 3   | Consent is recorded with timestamp, app version, policy version, locale           | `OnboardingViewModel.recordConsent` → `event_log` row `CONSENT_GRANTED`                                                                                                                               | ✅                                                                     |
| 4   | Only provider-address messages are processed                                      | `AddressAllowlistTest` — exact match, case-insensitive, **substring spoof rejected** ("bKash-Promo" does not match), unknown address fails closed                                                     | ✅                                                                     |
| 5   | Non-provider SMS leave no trace in storage or logs                                | `SmsReceiver` applies the allowlist **before** `CaptureSms` runs; nothing is written or logged on the reject path                                                                                     | ✅ (design + unit; instrumented assertion runs on the emulator CI job) |
| 6   | A privacy policy exists, is accurate, and is linked in-app                        | `docs/privacy-policy.md`; string `onb_privacy_policy` in both languages                                                                                                                               | ✅ (hosting URL pending deployment)                                    |
| 7   | Permissions are revocable and the app degrades safely                             | Revoking SMS permission stops capture; `InboxScanner` returns empty rather than crashing; Diagnostics reports the state and names the fix                                                             | ✅                                                                     |
| 8   | Revoke-and-wipe removes credentials and local data                                | `RevokeAndWipe` — cancels all work, `CredentialStore.wipeAll()`, `db.clearAllTables()`, and warns first with the count of undelivered payments                                                        | ✅                                                                     |
| 9   | Retention is enforced server-side (§17.3)                                         | `maintenance.spec.ts` — SMS text redacted past each company's retention while the extracted fields and verification survive; webhook bodies, auth attempts, match attempts and device events aged out | ✅                                                                     |
| 10  | Retention is enforced on-device                                                   | `PurgeWorker` deletes `UPLOADED` rows past 30 days and **never** touches an unsent row (`SyncQueueTest.retentionNeverDeletesUnsentMessages`)                                                          | ✅                                                                     |
| 11  | No unrelated personal SMS are collected — demonstrated, not asserted              | Items 4, 5 and 10 together; the `DiagnosticsSnapshot` type has no field for a message body, so the support bundle cannot leak one (`DiagnosticsFormatterTest`)                                        | ✅                                                                     |
| 12  | Distribution is a direct signed APK; the Play restriction is documented           | `docs/android-setup-guide.md` + `architecture.md §17.1`; `android-release.yml` builds and verifies the signature                                                                                      | ✅                                                                     |
| 13  | The client agreement states what the platform asserts and the merchant's own duty | `docs/client-agreement-notes.md` (EN + BN): _"a credit SMS consistent with this order was received on the registered device"_, not that funds settled                                                 | ✅                                                                     |
| 14  | Secrets are encrypted at rest and never logged                                    | `CryptoService` (AES-256-GCM, KEK outside the DB); webhook signature redacted in delivery history (`delivery.spec.ts`); device token redacted in app logs                                             | ✅                                                                     |
| 15  | Data is excluded from cloud backup and device transfer                            | `data_extraction_rules.xml`, `allowBackup="false"`                                                                                                                                                    | ✅                                                                     |

## Outstanding

- **Native Bengali review** of every user-facing string, including error and notification paths, at 1.3×
  and 2× font scale (item 2).
- **Publish the privacy policy at a stable URL** and point the in-app link at it (item 6).
- **Instrumented proof for item 5** — the "personal SMS leaves zero trace" assertion runs on the
  emulator CI job (`android.yml`), which has not been executed in this environment.
